# Alexa スキル「チャッピー」スーパーエージェント化 — 方向性マップ

**日付**: 2026-05-11
**ステータス**: 方向性ブレスト（決定前）
**目的**: 既存スキルを「スーパーエージェント」に進化させるための方向性を網羅し、深掘りする領域を選ぶための地図を提供する。

---

## 現状サマリ

- **頭脳**: OpenAI Responses API (`gpt-4.1-mini`) + Gemini（`research_web` ツールで Google 検索代行）
- **既存ツール**: Google Calendar / SwitchBot（エアコン・ON/OFF・温度・モード）/ Slack 送信 / 買い物リスト / Web 調査
- **会話文脈**: セッション内の `previousResponseId` チェーン + 会話ログ
- **長期記憶**: DynamoDB に 1000 文字以内の要約を保存（ユーザー単位 = Alexa userId 単位）
- **モーニングブリーフィング**: 天気・カレンダー予定・服装アドバイス
- **デプロイ**: AWS Lambda（ap-northeast-1、30 秒タイムアウト）
- **利用者**: 石井健・石井奈緒の夫婦（どちらが話すかは Alexa からは区別できない）
- **関連プロジェクト**: pairpanel（旧 ken-nao）

### 現状のアーキテクチャ上の特徴

- 受動型: ユーザーの発話 → 1 リクエスト → 応答、で完結
- 30 秒制限の中で Plan-Execute・複数 tool round（最大 3 ラウンド）まで実行可能
- メモリは「単一要約」型（ベクトル化されておらず、ユーザー区別もしていない）
- プロアクティブ通知（push 通知）の仕組みは未導入

---

## 方向性マップ（12 方向 / 4 グループ）

### 🧠 A. 賢さ系（中身を強化）

#### A-1. 推論強化
- **狙い**: 複雑な依頼に答えられる脳にする
- **施策案**:
  - モデル更新（`gpt-4.1-mini` → `gpt-5` / Claude Opus / Gemini 2.5 Pro 等）
  - Plan-and-Execute パターン（先に計画 → 個別実行 → 統合）
  - 自己反省ループ（Reflexion 風、応答前にセルフレビュー）
  - 多段推論（chain-of-thought の構造化）
- **トレードオフ**: 遅延・コスト増。30 秒制限との衝突。

#### A-2. メモリ強化
- **狙い**: 「知ってくれてる感」を出す
- **施策案**:
  - ベクトル記憶（RAG: 過去会話・好み・出来事を埋め込み検索）
  - エピソード記憶（「○月○日に××を話した」想起）
  - 「覚えておいて」明示コマンド
  - ユーザー別記憶（A-3 と連動）
  - DynamoDB → OpenSearch / Pinecone / pgvector への移行
- **トレードオフ**: 検索遅延、ストア追加コスト、要約品質依存。

#### A-3. 文脈認識
- **狙い**: いつ・誰が・どこで話しているかを理解する
- **施策案**:
  - 声紋識別（健 vs 奈緒）— Alexa Voice ID / 自前判定（音声入力は取れない制約あり、要検証）
  - 時間帯適応（朝・昼・夜で口調や提案を変える）
  - 位置情報連動（家にいる前提、外出時 pairpanel と連携？）
  - 「前回の続き」復帰（セッション跨ぎ）
- **トレードオフ**: Alexa の API 制約上できないことが多い可能性。

#### A-4. 会話品質
- **狙い**: 機械くささを消す
- **施策案**:
  - キャラ設定の強化（システムプロンプト・人格定義）
  - 相槌・確認の自然化
  - 感情検知（Alexa の感情シグナルは限定的、音声プロソディの利用）
  - フォローアップ提案（「ついでに天気も見ようか？」）
- **トレードオフ**: 過剰な雑談で本来の用途を阻害するリスク。

### 🛠️ B. できること系（ツール拡充）

#### B-5. 生活インフラ
- Gmail 読み上げ・送信
- 乗り換え案内（駅すぱあと API / Google Maps Directions）
- 地図・経路（Google Maps）
- Tabelog / ホットペッパー（飲食店検索・予約）
- Amazon 購買（買い物リスト → 実購入）
- ニュース（Yahoo!ニュース・NHK API）

#### B-6. スマートホーム拡張
- Philips Hue（照明）
- ロボット掃除機（Roomba / Switchbot K10+）
- スマートロック（Sesame / Switchbot Lock）
- TV 制御（Switchbot Hub Mini 経由）
- Spotify / Apple Music
- 睡眠データ（Oura / Fitbit / Apple Health）

#### B-7. タスク・ナレッジ管理
- Todoist / Google Tasks（既存買い物リストの拡張）
- Notion / Obsidian（メモ・知識ベースとの双方向）
- 習慣トラッキング（「今日も運動した？」）

#### B-8. 夫婦特化機能
- 二人の予定すり合わせ（健・奈緒のカレンダー両方を見て空き探索）
- 買い物リストの分担（「これは健が買う」管理）
- 家族タスク（家事ローテ）
- 「奈緒に伝えて」→ Slack DM / LINE 送信
- 記念日・誕生日リマインダー
- 二人だけの共有メモ

#### B-9. マルチモーダル / pairpanel 連携
- Echo Show 表示（APL = Alexa Presentation Language）
- 画像入力（Echo Show のカメラ、または手動アップロード）
- pairpanel への handoff（音声で指示 → pairpanel に表示）
- pairpanel から逆方向（pairpanel の通知をチャッピーが読む）

---

### 📢 C. 主体性系（受動 → 能動）

#### C-10. プロアクティブ通知
- **狙い**: 聞かれる前に伝える
- **施策案**:
  - Alexa Notifications API / Proactive Events API
  - 雨予報 → 「傘持ってって」リマインド
  - カレンダー変更追従（直前のリマインド）
  - 異常検知（電気つけっぱなし、温度異常、定例予定の抜け）
  - 定時ブリーフィング自動配信（朝のニュース・夜のまとめ）
  - cron + EventBridge での定期実行
- **トレードオフ**: スパム化リスク、通知疲れ。設計が要。

#### C-11. エージェント的ワークフロー
- **狙い**: マルチステップな依頼を任せられる
- **施策案**:
  - Plan-Execute フレームワーク（高レベルゴール → サブタスク分解 → 順次実行）
  - 非同期バックグラウンドタスク（Lambda の 30 秒を超える処理を SQS / Step Functions で）
  - 承認フロー（「これでいい？」→ 「うん」→ 実行）
  - ブラウザ自動化（Playwright / Browser Use → 食べログ予約、Amazon 注文）
  - 「来週の連休に旅行候補出して、空いてる日と天気と予算で 3 案」のような依頼
- **トレードオフ**: 失敗時の挙動設計、ブラウザ自動化はインフラ重い。

### 🎙️ D. 体験系（仕上げ・運用）

#### D-12. 音声強化・安全性
- Polly Neural 音声（標準より自然）
- SSML 豊かな表現（間・強弱・感情）
- OpenAI Realtime API（低遅延・割り込み対応会話）
- 音声 PIN（家電操作・購買・送信系で）
- コスト監視・レート制限
- エラーリトライ・フォールバック強化

| 軸 | 説明 |

| インパクト | 体感「スーパーになった」度合い |

## 僕の推し（仮説）

**最大インパクト**: **C-11 エージェント的ワークフロー** + **C-10 プロアクティブ通知**

理由：

- 今のチャッピーは「聞いたら答える」受動型。能動化が一番「別物になった」感が出る。
- 既存ツール（カレンダー・SwitchBot・Slack・Web 調査）をそのまま再利用しつつ、「組み合わせて使う」次元が増えるので投資効率がよい。
- 「異常検知 → 通知」「マルチステップ依頼」は他にない体験で、家族の生活インフラに食い込める。

**次点**: **A-2 メモリ強化**（ベクトル記憶＋ユーザー別記憶）— 上のエージェント化が活きる土台になる。

**併走候補**: **B-8 夫婦特化**（二人のカレンダー突合せ等）— 利用者が夫婦である強みを活かせる。
